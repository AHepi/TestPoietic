## What this is

Two more undefined words get proposed meanings, pinned together because
they are joined inside one frozen abbreviation: SameSyntax (two things
have the same code/label presentation) and RealizationEq (two things play
the same causal role for a declared task in a declared environment). The
abbreviation SameLabelSwap joins them with a NOT: same syntax AND not the
same role. The frozen row N18 merely says such a pair exists — and the
project's own inventory marks N18 "do not test or repair," because this
pair of definitions is where a careless choice rigs the row in either
direction.

## Why they had to be pinned together

If "same syntax" were defined loosely, the row would be satisfiable for
free. If "same role" were defined loosely, its negation would never hold
and the row would be impossible. The record therefore adds a joint rule:
after pinning, there must still be a possible structure with a swap (same
label, different role — for instance a pair differing only in idle
metadata) and a possible structure without one (every same-label pair is
an exact role duplicate). Both are exhibited. The pin makes the row
testable someday without deciding it.

## The role reading, and why

RealizationEq is pinned as equality of the counterfactual causal role
profile across the declared variants of the bearer in the declared
environment — constrained by the source register's rule that realization
roles are contextual, so a one-off output match does not count. This is
the reading under which the project's earlier target-essentiality finding
(changing only idle metadata while the operative program stays fixed)
counts as a role difference, exactly as intended. The rejected readings —
same observed output, and same-syntax-implies-same-role — would destroy
the row; both are recorded with reasons.

## What did NOT change

Nothing was tested, repaired, or discharged; N18 keeps its do-not-test
marking and stays open. Counts stand at 0 pinned, 2 partial, 18 open;
