## What problem this fixes

Before this annex, a supposed counterexample could cheat.

It could say:

- “this population has selection,”
- “this system does not have high-quality self-reproduction,” or
- “this episode is not creative,”

without saying exactly what those words mean in the example.

That is too easy. If the words are not pinned down, someone can just choose
which statements are true or false.

This annex says that future examples must use small, fully listed models.
The model has to show its parts, its actions, its inputs, and its rules.

## The three kinds of model

### 1. A population model

This is for cases about variation, inheritance, selection, later copying, and
different outcomes under a named condition.

The future model must list:

- the members of the population;
- which one came from which parent;
- what variation happened;
- the common condition they faced;
- what happened differently because of that condition; and
- how a later member copied or re-used the surviving information.

It is only a model of a named small case. It does not prove something about
all life, all evolution, or all systems.

### 2. An agent-and-episode model

This is for a sequence like:

problem → tentative idea → test or criticism → later revised problem or idea.

The future model must list:

- the actual steps in that sequence;
- the evidence and test result used;
- where the evidence came from;
- which inputs were seeds or external inputs;
- a revision that really responds to a possible bad result; and
- which actions were actually performed by the named agent.

A ready-made note, idea, or score sitting in the system does not count as the
agent creating, evaluating, or promoting it. The model has to show an
agent-owned action that produced the relevant item.

### 3. An interface model

This stops a subtle cheating move: joining pieces from different cases because
they have the same label.

For example, an episode might refer to a knowledge item called “recipe A,”
and a physical system might also contain something called “recipe A.” They
cannot be joined merely because the words match.

The model must show that the same actual items match:

- the information item;
- the physical bearer and knowledge item;
- the evidence package;
- the time and trace;
- the environment;
- where the evidence came from;
- the program used;
- the task, boundary, and continuing frame.

If one of these does not match, the records must stay separate. That means the
stronger conclusion is not established. It does not mean the system is proved
non-creative.

## Two separate questions

Every future non-entailment result has two separate labels.

1. **Have we made the model?**
   - Registered: we know what model we need.
   - Under construction: a candidate model exists.
   - Discharged relative to a named class: an independent checker accepted a
     specific model.

2. **Are the important words pinned down?**
   - Unpinned: important words can still be interpreted freely.
   - Partly pinned: some meanings are fixed, others are not.
   - Pinned for a named class: the needed meanings are fixed in that one
     small class.
   - Adequacy unclaimed: we do not claim the small class covers every real
     case.

A checked small model is not a universal proof. It is only a result about the
small class that was named and frozen first.
## Important limits

A checked example is still **not** a completed result for one of the project’s
original non-entailment rows. To reach that stage, the example has to be
completed into a full model of the frozen rules, checked by someone
independent, and linked back to the exact original row with a separate
argument. Until then it is only a checked example in a small class.

The copying test in this annex is deliberately small. It checks one named,
finite copying protocol. It does **not** settle whether a real physical system
can copy itself with unlimited, indefinitely improving, or universally high
accuracy.

We will also test deliberately broken versions of the rules. If the checker
rejects a broken version, that shows it caught that named mistake. It does
**not** show that every important word has been pinned down or that the small
model class is a perfect picture of reality.

## What happens next

The next record can build a few concrete small examples:

- a selected population that does not have the annex’s finite
  high-accuracy-copying route;
- a one-off problem–idea–test–revision episode that does not show a lasting
  creative capacity; and
- two deliberately bad joins between otherwise valid records, to make sure
  the interface checks reject them.

Before one of these is called a discharged result, it must name this annex
version, its hash, the exact model class, the frozen calculus, and an
independent replay. To connect it back to an original project claim, it also
needs a separate bridge showing that the small model really represents that
original claim.

## What this does not say

This record does not say that constructor theory, Popper’s ideas, Deutsch’s
ideas, or the project’s bridges are true. It does not say that passing a
check proves creativity. It does not say that a failed check proves a system
is not creative.

It only makes later tests harder to fake and easier for someone else to
inspect.
