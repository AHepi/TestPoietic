# TestPoietic

This repository is an auditable stress-test package for the exact attachment
`subject/spark-poietic-layered-kernel-v1.2-purpose-guarded.md`.

The primary subject is byte-pinned by SHA-256:

```text
9c5d389afc1f334733604083710f6625638b8933825a6312c7403e7de08dafbc
```

The repository separates four things that the kernel itself says must not be
collapsed: source authentication, proof/model criticism, executable field
protocols, and interpretation. A green verifier means only that the recorded
evidence reproduces; it is not a truth or support grade for the theory.

## Result

The exact attachment does not yet qualify as an audit-ready, fully determined
layered theory. Four source/protocol defects are derived directly: F8-D negates
the wrong quantifier for \(R_G\), the prose refuter for \(R_X^\Phi\) has the
same scope error, Conjecture O has no executable F6 verdict rule, and F3's
policy arms are not closed or mutually exclusive. The P3.5, W3-to-A5,
finite-prefix, T7, and TRef witnesses expose serious semantic seams, but their
reduced encodings do not close every source premise and are therefore reported
as `UNDERDETERMINED` or `UNVERIFIED`, not as full formal counterexamples.

The finite acquisition results survive their bounded exhaustive campaign, and
the prior F1 result independently reproduces as
`REFUTED ON THIS DECLARED DOMAIN`.

Read the [stress-test report](docs/STRESS_TEST_REPORT.md) and the
[claim-status matrix](docs/CLAIM_STATUS.md) before using any green checker as a
theory verdict.

content-addressed semantic/preregistration freeze: it pins the subject, prior

`71fae96d7103e695a4c955ad7c46c8b19afc6a5a` then changed three launcher files
and added the preserved failed-attempt record; no model semantics, population,
prediction, or decision rule changed.
Commit `f0680881d0ca7411a4f15dc447c2800052f6e567` records the successful raw
campaign and the report reviewed independently. The package therefore claims
a semantic freeze followed by a disclosed launcher repair, not an unchanged
executable tree from preregistration through execution.

Run the complete verifier from the repository root:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -B scripts/verify_repository.py
```

The verifier uses only the Python standard library. Generated files are
written to a caller-selected external directory, never silently into the
authenticated source tree.

## Evidence rule

Every reported verdict must name its exact subject hash, executable boundary,
input population, predicted observable, raw output, and scope. Failure of a
witness blocks the application that needs it; it is not silently counted as a
refutation of an unrelated theorem. A raw field named `counterexample` means
only “counterexample to the encoded reduced predicate”; the
[premise-closure table](docs/PREMISE_CLOSURE.md) determines whether that result
can be promoted to a verdict on the source claim.
